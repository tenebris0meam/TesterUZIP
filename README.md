# Тестер УЗИП (tester-uzip)

Прошивка настольного тестера устройств защиты от импульсных перенапряжений (УЗИП) на микроконтроллере **STM32F103C8T6**. Тестер подаёт на испытуемый прибор регулируемое высокое напряжение (до 550 В), измеряет напряжение и ток через прецизионный монитор **INA239** и выносит вердикт «исправно / неисправно» по каждой проверке. Результаты отображаются на графическом дисплее **MT-12864B** (контроллер NT75451).

Поддерживаемые типы защитных компонентов:

| Тип | Обозначение в коде | Что проверяется |
|-----|--------------------|-----------------|
| Диод (TVS) | `TransientVoltageSupressor` | напряжение пробоя и ток в окне 0.9…2 мА |
| Варистор | `Varistor` | то же, с другими порогами напряжения |
| Газовый разрядник (GDT) | `GasDischargeTube` | напряжение зажигания (усредняется по 3 пускам) и факт срабатывания |

## Аппаратная часть

| Узел | Компонент | Назначение |
|------|-----------|------------|
| МК | STM32F103C8T6 (Cortex-M3) | кварц 8 МГц, PLL → **60 МГц** (HSE/2 × 15); APB1 = 30 МГц, APB2 = 60 МГц |
| Монитор | INA239 (SPI) | измеряет напряжение на шине (через делитель) и падение на шунте |
| Дисплей | MT-12864B, контроллер NT75451 | 128×64, SPI, полудуплекс на передачу |
| Генератор ВН | ШИМ TIM1 CH1 (PA8), 60 кГц | преобразователь напряжения; скважность задаёт регулятор |
| Коммутация | 2 мультиплексора (8 линий) + 4 реле | подключение щупов / клеммника K1 / разъёма RJ45 |
| Индикация | зуммер, 4 кнопки | звуковой сигнал и управление |

Основные параметры измерительной цепи (`hv_feedback.h`):

- делитель напряжения: R1 = 519 кОм, R2 = 76.2 кОм (82.5 кОм ‖ 1 МОм входного импеданса VBUS), коэффициент **K ≈ 7.81**;
- максимальное напряжение теста: **550 В** (проверяется `_Static_assert` на этапе сборки: образ на входе INA239 не должен выходить за порог 82.5 В);
- шунт: **22 Ом**, максимальный ожидаемый ток 2 мА (`_Static_assert` по порогу шунта 163.84 мВ);
- INA239: диапазон шунта ±163.84 мВ (5 мкВ/LSB), шина 3.125 мВ/LSB, время преобразования 50 мкс, без усреднения.

## Архитектура прошивки

Прошивка — главный цикл (`main.c`) плюс три прерывания, обслуживающие измерения. Операционной системы нет.

```
main loop
 ├─ proccessor_take_event() → proccessor[state].handle_event()  → смена состояния (on_exit/on_enter)
 ├─ proccessor[state].proccess()
 ├─ buzzer_routine()
 └─ display_routine()   (если отрисовка разрешена)
```

### Приоритеты прерываний

| Прерывание | Приоритет | Роль |
|------------|-----------|------|
| `TIM1_BRK` | 0 (высший) | аппаратная авария по ALERT INA239: отключает ШИМ и коммутацию |
| `DMA1_Channel4/5` | 1 | завершение обмена SPI2 (RX/TX) |
| `TIM3` | 2 | периодический запрос измерений у INA239 (10 кГц при 50 мкс на канал) |
| `TIM4` | 15 | опрос клавиатуры каждые 10 мс |

### Конечный автомат проверки (`proccessor.c`)

```
Idle_Setting ──Enter──► Commutation ──► Generation ──► TestPassed / TestFailed
     ▲                      ▲                                  │
     │                      └──── есть ещё проверки ───────────┤
     │                                                         ▼
     └──────────────── TestSequenceComplete ◄── проверок больше нет
              (из любого состояния по AlertActive ──► HardwareFail)
```

| Состояние | Что делает |
|-----------|------------|
| `Idle_Setting` | ожидание команды оператора; восстанавливает штатные пороги INA239 |
| `Commutation` | выставляет линии очередной последовательности, замыкает коммутацию |
| `Generation` | регулятор выводит напряжение на уставку, модуль `calc` классифицирует результат |
| `TestPassed` / `TestFailed` | фиксируют результат в модели и поднимают событие перехода |
| `TestSequenceComplete` | сигнал оператору, экран итогов |
| `HardwareFail` | обесточивание, чтение причины из `DIAG_ALRT`, экран ошибки |

Обработчики состояний `Generation` и `HardwareFail` подменяются через `resolver.c` в зависимости от типа компонента (TVS/варистор или GDT).

События (`Event`) поднимаются потокобезопасно (`proccessor_raise_event`, `proccessor_force_raise_event`); аварийное событие `AlertActive` вытесняет любое другое.

## Алгоритм проверки

Для каждой пары выводов из конфигурации:

1. **Коммутация.** `proccessor_setup_lines()` проверяет допустимость диапазона напряжений и линий, коммутатор подтверждает принятие обеих линий. При ошибке проверка засчитывается проваленной, высокое напряжение не подаётся.
2. **Генерация (TVS и варистор).** Уставка начинается с `min_voltage`, затем поднимается на шаги по 1/10 диапазона (`GENERATION_MAX_STEPS = 10`) после выхода напряжения в допуск ±5 %. На каждом шаге работает сторожевой таймер 3 с.
3. **Режим стабилизации тока (CC).** Когда ток достигает 0.1 мА, регулятор переходит от стабилизации напряжения к стабилизации тока около 1 мА (максимальная скважность ограничена 97 %), таймаут 3 с.
4. **Вердикт.**
   - ток ≥ 2 мА → перегрузка (проверка провалена, если напряжение вне окна теста);
   - напряжение ≥ `max_voltage` → превышение, провал;
   - напряжение в окне и ток в диапазоне **0.9…2 мА** → проверка пройдена;
   - таймауты и исчерпание уставок → провал.
5. **Разрядник (GDT).** Три пуска подряд: напряжение растёт до порога срабатывания, срабатывание фиксируется по ALERT INA239 (порог шунта ≈ 2 мА) и считается успехом. Результатом становится среднее по трём пускам максимальное напряжение.
6. **Остановка.** При выходе из состояния `Generation`: останавливается ШИМ, обнуляется скважность, ожидается разряд конденсатора генератора, INA239 уходит в shutdown, коммутация размыкается.

Три нажатия `Cancel` во время проверки отменяют её (экран «тест отменен оператором»).

## Измерения и обратная связь

- INA239 работает в режиме `CONT_SHUNT_BUS`. Таймер TIM3 каждые `(Tvbus + Tshunt) × AVG` мкс запускает обмен по DMA: кадр из 6 байт читает регистры `VBUS` (0x05) и `VSHUNT` (0x04).
- `calc_measurement_update()` берёт снимок кадра под запретом прерываний (чтобы напряжение и ток были из одного измерения) и вычисляет:
  - напряжение: `VBUS − падение на шунте` (мкВ);
  - ток: `Uшунта / 22 Ом` (нА).
- Регулятор — интегратор в миллионных долях скважности (`CALC_DUTY_MAX_PPM = 970000`) с ограничением скорости нарастания уставки (≈ 500 В/с на выходе генератора).
- Скважность пересчитывается в регистр сравнения TIM1 (ARR = 999 → 60 кГц).
- Если новые данные не поступают дольше ~100 периодов опроса, генерация останавливается (`is_data_old`).

## Шина SPI2 и арбитраж

Шину делят INA239 (обмен из прерывания TIM3) и дисплей (из главного цикла). Правила (`spi.h`):

1. Доступ к шине только через `spi2ctrl.capture()` / `release()`.
2. `capture()` атомарен и **не отбирает** шину у текущего владельца.
3. `capture()` сам настраивает режим CPOL/CPHA и направление: INA239 — SPI mode 1, полный дуплекс; дисплей — mode 0, полудуплекс TX.
4. Из прерывания шину не ждут: занято — такт пропускается.
5. Между транзакциями SPI2 остаётся включённым в режиме INA239.
6. Завершение обмена INA239 (полный дуплекс) обслуживает обработчик DMA; завершение обмена с дисплеем доводит владелец в главном цикле через `wait_done()`.

## Коммутатор

`commutator.c` управляет реле и мультиплексорами в зависимости от выбранного интерфейса (`Param_Connector`):

| ID | Интерфейс | Доступные линии |
|----|-----------|-----------------|
| 0 | `Probe` (щупы Щ1/Щ2) | 1 и 2 |
| 1 | `RJ45` (FTP) | 1…9 (9 — экран) |
| 2 | `K1` (клеммник) | 1…5 |

Линии 1…8 коммутируются мультиплексорами, линия 9 — реле экрана RJ45. Коммутатор отказывает молча при недопустимой линии, поэтому процессор проверяет результат через `commutator_get_active_line()`.

## Безопасность

Это установка с высоким напряжением, порядок действий — не косметика:

- скважность обнуляется **до** включения выходов TIM1; выходы гасятся **до** размыкания реле;
- вход BKIN таймера TIM1 подключён к ALERT INA239: при срабатывании порога ШИМ отключается **аппаратно**, не дожидаясь ПО;
- `TIM1_BRK_IRQHandler` мгновенно размыкает коммутацию без задержек (`commutator_forcedeny_commutation`) и поднимает `AlertActive`;
- у INA239 включена защёлка ALERT (`ALATCH`); снимается чтением `DIAG_ALRT` в `HardwareFail`;
- ни одна проверка не начинается, пока коммутатор не подтвердил обе линии;
- на каждом шаге уставки работает сторожевой таймер, вердикт по току выносится только после выхода регулятора на уставку;
- причины аварии (`typefail`): перегрузка по току/напряжению, недогрузка, переполнение вычислений, ошибка памяти INA239;
- при невосстановимой ошибке инициализации вызывается `Error_Handler()` — зуммер мигает 1 Гц.

## Дисплей и интерфейс оператора

### Отрисовка

Полный кадр в ОЗУ не хранится: экран делится на 8 полос по 8 пикселей, в памяти живёт одна полоса (128 байт). Кадр рисуется циклом `fb_begin_band` → `render()` → `fb_flush_band()` по каждой полосе (`framebuffer.c`). Функции рисования сами отбрасывают всё вне текущей полосы.

Инициализация контроллера NT75451 (`lcd_init`): включается внутренний повышающий преобразователь (`0x2F`), делитель V0 и электронный регулятор контраста, нормальное отображение, обратный порядок COM (`0xC8`), включение дисплея (`0xAF`).

### Шрифты и кириллица

Шрифт `cgxyz` 6×8 (есть также `jetbrains` 7×13). Кириллические глифы лежат в кодах ASCII, поэтому строки в `strings_def.h` выглядят «нечитаемо» (`"Reqr"` = «Тест»). **Эти определения менять нельзя**; соответствие кодов буквам — в `docs/markdown/character_table.md`.

### Экраны

`Hello → Выбор серии → Выбор группы → Выбор устройства → Главный → Подтверждение → Тест идёт → Итоги → Данные теста`; а также `Тест отменён` и `Аппаратная ошибка`. При `TESTER_MODES` добавляются экраны режимов и генератора.

### Кнопки

| Кнопка | Событие |
|--------|---------|
| Up | `InputEvent_ButtonPressed_Previous` |
| Reject | `InputEvent_ButtonPressed_Cancel` |
| Down | `InputEvent_ButtonPressed_Next` |
| Accept | `InputEvent_ButtonPressed_Enter` |

Антидребезг 50 мс, события выдаются по фронту.

## Конфигурация приборов

Каталог приборов хранится в `config/new_config.json` и **не разбирается в рантайме**. При сборке `tools/minify_json.py` генерирует `build/config/config_data.c` с готовыми `const`-структурами, которые линкуются в секцию `.config` (регион `CONFIG`, 8 КБ Flash). Расход ОЗУ — ноль. Прошивка лишь проверяет сигнатуру и версию (`configurator_read_config()`).

Формат файла — массив:

- **элемент 0 — каталог**: `Series`, `Groups`, `DevicesNames`, `Sequences` (пары `InputPin`/`OutputPin`, 0…8), `TestParams` (3 типа: TVS, варистор, GDT; в каждом — `MinVoltage`/`MaxVoltage`);
- **элементы 1…N — приборы**: `SeriaID`, `GroupID`, `DeviceID`, `TestSequences` (три «ведра» по типам с парами `SequenceID`/`TestID`), `ConnectorID` (0 — щупы, 1 — RJ45, 2 — K1).

Генератор строго валидирует конфигурацию: диапазоны, сортировку приборов по (серия, группа), совпадение индексов с позициями, лимит 32 проверки на прибор, размер блока. Имена пишутся в закодированной кириллице (см. выше). Текущий каталог: 2 серии, 13 групп, 41 прибор, 72 последовательности.

Запуск вручную:

```bash
python tools/minify_json.py -i config/new_config.json -o build/config/config_data.c
```

## Сборка

Требуется:

- ARM GNU Toolchain (`arm-none-eabi-gcc`), файл `arm-none-eabi.cmake` в корне;
- CMake ≥ 3.20, MinGW Make;
- Python 3 (генерация конфигурации);
- библиотека **STM32CubeF1** (пути заданы в начале `CMakeLists.txt`: `WORKSPACE_PATH`, `STM32CUBE_DRIVERS`).

```bash
cmake --preset debug      # или release
cmake --build build
```

Результат: `tester-uzip.elf`, `.bin`, `.hex`, `.map` в каталоге `build/`.

Флаги компиляции: `USE_FULL_LL_DRIVER`, `STM32F103xB`, `DEBUG` (только для Debug; в нём используется другая калибровка `SHUNT_CAL_RAW`). Release собирается с `-Os`.

## Прошивка и отладка

Подключение через ST-Link и OpenOCD (`my_f103.cfg`).

```powershell
# прошивка (.elf, .hex или .bin; для .bin адрес 0x08000000 подставляется сам)
.\firmware_stm32f103c8t6.ps1 -FirmwareFile build\tester-uzip.elf

# полное стирание памяти МК
.\erase_stm32f103c8t6.ps1
```

В `PATH` должны быть `openocd` и `arm-none-eabi-gdb`. Скрипты поднимают OpenOCD в фоне, выполняют команды через GDB и завершают OpenOCD.

## Режимы работы (`TESTER_MODES`)

При включённом макросе доступны экраны выбора режима:

| Режим | Описание |
|-------|----------|
| Проверка прибора | основной режим, описан выше |
| Вольтметр | непрерывное измерение напряжения и тока на щупах |
| Омметр | возбуждение 5 В, расчёт сопротивления по усреднённому току (окно 32 отсчёта, контроль разброса) |
| Генератор | ручная установка напряжения 1…550 В, отключение при токе ≥ 1 мА |

- `STM32F103C8T6.pdf` — микроконтроллер;
- `INA239.pdf` — монитор тока и напряжения (регистры, SPI-кадры, расчёт `SHUNT_CAL`);
- `MT-12864B.pdf` — модуль индикатора;
- `NT75451` — контроллер индикатора (команды, инициализация, тайминги SPI).
